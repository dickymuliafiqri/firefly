# End-to-end audit — 2026-09-22

Sandbox run in **file-config mode** (`-config-dir`, no Turso) against a Bun mock
upstream (`/_mock/seen`, `/_mock/force?status=&count=&retry_after=`, `/_mock/slow`,
`/_mock/reset`). Flow exercised: create upstream via dashboard → model discovery →
tenant + gateway key → data plane (`/v1/models`, `/v1/chat/completions` JSON+SSE,
`/v1/usage`) → Playground.

## Verified working

- Upstream creation via dashboard UI → `PUT /api/settings` 200; credential pool with
  inline `api_key` accepted in file mode.
- Model discovery (`POST /api/upstreams/models`) → route `mock-public` → upstream
  `mock-model-1`, public→private rewrite on the wire.
- Tenant creation + gateway key (`sk-gw-...`) auth on `/v1/*`.
- Data plane: `GET /v1/models`, `POST /v1/chat/completions` (JSON + SSE),
  `GET /v1/usage` (metering: `used_tokens` increments).

  `Connection: keep-alive`, `X-Accel-Buffering: no`, `X-Request-Id` propagated, chunked.
- Layer 1 failover: forced 429 on key-1 → transparent retry on key-2 → client got 200.
  Key-1 `total_cooldown_events` +1.
- Breaker stayed `CLOSED` through all 4xx (no false outage); `circuit_trips: 0`.
- Telemetry SSE inspector (`GET /api/telemetry/events`): `: connected` + two
  `event: log` frames per request (start with status 0, then completion with status 200).
- Playground: full round-trip with Token Stream Waterfall (TTFT 71 ms, 14.4 t/s,
  2 chunks) and RAW SSE Packet Inspector (4 frames incl. `data: [DONE]`).
- `GET /api/breakers`, `GET /api/telemetry`, `GET /api/history` serve consistent
  per-request data incl. `keyRef`, tokens, cost.
- WARP: live Cloudflare session (SIN colo, IPv6 egress, endpoint 162.159.192.1:2408),
  rotation to a new public IP with `draining_sessions: 1`, WireGuard handshake logs,
  identity persisted at `<configDir>/data/warp_identity.json`; direct vs warp egress
  both reached a public HTTPS host (418 ms vs 397 ms).
- TokenSaver engine via `POST /v1/compress`: 310 → 171 chars (ANSI strip, repeat
  collapsing, head/tail truncation, brevity directive injection).
- Background workers alive: watcher, usage exporter, health checker, OAuth refresher,
  analytics store, AutoTLS. Analytics JSON rewritten after each request; history
  survives restarts.

## Bugs found

### B1 (high) Typed-nil `Notifier` panics the request → HTTP 500

`cmd/firefly/main.go` (~line 343 + 7 more adapter configs) always assigns
`Notifier: usageFlusher`, but `usageFlusher *turso.UsageFlusher` is nil in
file-config mode. `internal/transport/upstream/policy.go:70,107,143` guard with a
bare `notifier != nil` → the typed-nil interface passes the check → nil receiver
deref at `internal/storage/turso/flusher.go:122` (`f.logger.Warn`).

**Observed:** forced 429 ×3 with `key_error_threshold=3`, `key_error_action=deactivate`
→ panic recovered by `RecoverMiddleware` → client received **HTTP 500** (empty body)
instead of 429. The panic also skips the `"msg":"request"` log line (Recover sits
outside Logging) and leaves a history row stuck at `status: 0` rendered as "ACTIVE".

Violates AGENTS.md invariant #3 (`httpx.IsNil`), which is used correctly at
`router.go:74,79,91`, `settings.go:498`, `tenants_admin.go:568`, `authmw.go:28`.

**Fix:** use `httpx.IsNil(notifier)` in `policy.go` (no import cycle: `httpx` does
not import `upstream`).

### B2 (high) Config watcher rebuilds the whole catalog every 10 s unconditionally

`internal/watch/watch.go:113-114`: `case <-poll.C: w.signal(triggers, "poll")` with
no mtime/size/hash comparison. Log shows `config reloaded reason=poll generation=176`
every 10 s.

**Consequence:** every reload builds new `KeySlot`s → all in-memory key state
(cooldowns **and** the `deactivate`/`delete` threshold result) is wiped. A key
deactivated by the error policy is alive again ≤10 s later; observed
`is_revoked:false` 4 s after `key error threshold reached: deactivating key`.
Rotation fairness itself survives (it is anchored to the process-wide
`globalRotation` counter), but every rebuild still allocates a full snapshot +
KeyRings/Targets and bumps `firefly_config_generation`.

**Fix:** only signal when a watched file actually changed (compare mtime/size or hash);
skip `analytics.json`/`tls.json`/`auth.json`.

### B3 (medium) `global_admission.inflight` / `active_streams` are not what they claim

`RouterDeps.GlobalLimiter` is never set in `cmd/firefly/main.go` (field at
`router.go:55`, consumer at `telemetry.go:107`), so `handleGetTelemetry` always takes
the fallback branch and reports `metricsSnap.HttpInflight`. That gauge counts *every*
request including the ones documented to bypass admission (`/api/*`, `/healthz`) —
notably the long-lived `/api/telemetry/events` stream itself.

**Observed:** idle dashboard reports `inflight: 2`, `active_streams: 2`, while
Prometheus `firefly_global_inflight_requests = 0` and
`firefly_http_inflight_requests = 1`.

**Fix:** wire `GlobalLimiter` into `RouterDeps`, or read
`MetricsSnapshot.GlobalInflight` and derive streams from key inflight only.

### B4 (low) `/api/providers*` is turso-only and returns a raw error in file mode

`GET /api/providers` in file-config mode → 503 `{"error":{"message":"credential store
is not configured; provider administration requires turso storage"}}`. The Providers
dashboard cannot show the credential catalog that actually exists in `upstreams.json`,
and the frontend surfaces the raw backend message.

### B5 (high) TokenSaver is silently disabled in the chat path

`internal/registry/registry.go:60-69` (`BuildAndStore`, used at startup **and** on
every watcher reload) omits `domain.WithTokenSaver(res.TokenSaver)`, while
`internal/server/settings.go:497-509` (the `PUT /api/settings` path) includes it.

**Proof** (mock-side inspection of the body the upstream actually received):

1. Cold start with `tokensaver.json {enabled:true}` → ANSI **not** stripped, no RTK
   marker, 0 injected brevity directives.
2. Immediately after `PUT /api/settings` → ANSI stripped,
   `... [RTK: repeated N times] ...` present, 1 brevity directive injected.
3. One 10 s poll reload later → back to untransformed.

**Fix:** add the missing `domain.WithTokenSaver(res.TokenSaver)` option to
`BuildAndStore`.

## Efficiency / UX observations

- Health checker logs `msg:"upstream probe healthy", "status":429` — a 429 probe
  counts as "healthy" (host reachable) and puts the probed key in cooldown, but probe
  429s never increment `ConsecutiveErrors`. Wording is misleading.
- Secrets are duplicated in `upstreams.json`: each pool entry carries `api_key`
  (inline) and `secret`; raw `Authorization` headers can also appear in `headers`.
  Consider one canonical field per credential.
- A failed settings save leaves the modal closed and the row rendered (phantom ACTIVE
  upstream) — `UpstreamModal.tsx` calls `onClose()` even when `saveMutation` fails; the
  error is only visible as a toast.
- `allow_insecure` is required for any plain-http `base_url` but is buried on the
  "Timeouts & Sockets" tab; the validation message
  (`base_url must be https (or http with allow_insecure)`) is the only pointer.
- Frontend polls `/api/settings`, `/api/telemetry`, `/healthz` continuously
  (251/614/409 calls in ~40 min). `/api/telemetry` already contains everything the
  header needs, so the `/api/settings` polling is largely redundant.

### B1 — typed-nil `Notifier`

All three guards in `HandleKeyOutcome`/`applyKeyAction` now use the package-local
`isNil` (the same check `httpx.IsNil` performs; `httpx` cannot be imported here
because it transitively depends on the adapters). The doc comment records why a
bare `!= nil` is not equivalent.

**e2e:** four forced 429s → four 429 responses, `panic recovered` absent from the
log, `key error threshold reached: deactivating key` present, every attempt logged.
Before the fix the third attempt produced a 500 with no request log line.

### B2 — unconditional poll reload

The poll no longer signals a reload on every tick. A new `pollFingerprint(dir)`
hashes `name|size|mtimeNano` of the tracked files, and the tick only signals when
the fingerprint moved. fsnotify-served changes refresh that baseline, so a change
never reloads twice. `config.ConfigFileNames()` is now the single source of truth
for both the fsnotify filter and the poll fingerprint, so the two sets cannot
drift — `analytics.json`/`tls.json`/`auth.json` were never in the set and stay
ignored.

**e2e:** 12 s idle → 0 reloads, 0 `reason=poll`; the key deactivated by B1 stays
`revoked` and its pool reports `active_keys: 0`; one real edit to `models.json` →
exactly 1 reload, attributed to `fsnotify`, with no duplicate on the following
poll tick.

### B3 — telemetry admission numbers

`cmd/firefly/main.go` now constructs the global limiter once and injects it into
`RouterDeps.GlobalLimiter`, so the middleware chain and the telemetry handler read
the same instance. In `telemetry.go` the fallback that reported
`metricsSnap.HttpInflight` was replaced by the admission-observer gauge
(`GlobalInflight`) with the capacity from `httpx.DefaultGlobalMaxInflight`, and
`active_streams` is now the sum of per-credential in-flight counters only — both
bogus fallbacks (including the `HttpInflight - 1` "subtract the telemetry
connection" heuristic) are gone.

**e2e:** an idle dashboard reports `inflight: 0` against `capacity: 1500`,
`queue_depth: 0`, `active_streams: 0` while `/api/telemetry/events` had been
polled — previously that same state reported 2 in-flight streams.

### B4 — provider surface in file-config mode

New `internal/server/providers_file.go`: a read-only `providerAdminStore` that
projects the live snapshot (one provider per credential-carrying upstream, one key
per ring slot). Ids are FNV-64 hashes of the natural keys, so dashboard URLs stay
stable across reloads despite the snapshot being rebuilt each time. A
config-declared credential has no stored secret, so its hint is the masked ref;
a database-managed credential (harvested or operator-added) is hinted from its
secret fragment exactly as before. The resolver in `providers_admin.go` prefers a
configured Turso store, falls back to the snapshot, and only 503s when neither
exists; the list response carries `storage`/`read_only`, and every mutation
answers 501 naming `upstreams.json`.

The dashboard (`ProvidersView.tsx`, `ProviderKeyTable.tsx`, `schema.ts`) renders
that mode as a read-only catalog: banner, no edit/delete/add-key controls, no
Actions column, and the per-row provenance line says `from upstreams.json` instead
of implying a `-key-{id}` ref suffix.

**e2e:** `storage: file`, `read_only: true`, both pools listed, the key hint is the
masked ref (`moc...ey-1`), the raw secret is absent from the response, and a write
POST is refused with 501 naming `upstreams.json`.

### B5 — TokenSaver

`domain.WithTokenSaver(res.TokenSaver)` was missing from `registry.BuildAndStore`,
which runs at startup *and* on every watcher reload. The same hole existed in the
Turso path — `turso.LoadCatalogSnapshot` never put the settings-blob TokenSaver
back into the `config.FileSet`, so every database-backed snapshot also carried the
disabled default — and is fixed the same way. `registry_test.go` and
`store_test.go` pin both.

**e2e:** from a cold start the body the upstream receives carries the brevity
directive, the RTK marker (`... [RTK: repeated 4 times] ...`, five identical lines
collapsed to the kept last line plus the duplicate count), and no ANSI escapes;
after a reload the same three assertions hold.

### Bonus finding: the two OpenAPI version-stamping test failures

`TestOpenAPIAdminSpec_VersionStampedFromBuild` and its harvester twin fail only on
a Windows working copy with `core.autocrlf=true`: the specs are embedded as CRLF
bytes, and `infoVersionRe` (`(?m)^  version: "[^"]*"$`) cannot match a line ending
in `\r`, so `stampVersion` is a no-op and the served document keeps the embedded
placeholder. Release builds from a CRLF checkout therefore also serve an unstamped
`info.version`. Not fixed here (it is a checkout/build-configuration issue, not a
code defect); the 2 failures are expected locally and pass on LF checkouts.
